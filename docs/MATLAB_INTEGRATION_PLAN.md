# MATLAB Integration Plan — Harness Studio

> **Status:** Design only. No MATLAB execution exists.
> **Constraint:** Do **not** assume MATLAB is installed. Do **not** execute MATLAB
> code from agent output without explicit user consent and an environment check.

---

## 1. Why this matters

The user mentioned MATLAB integration as a near-term goal — typical use cases
include antenna-array factor scripts, parameter sweeps, simple optimization
problems, and CSV-driven simulation. The current architecture already supports
file-based agent outputs (artifacts) and consent-gated hook execution, which
maps cleanly onto MATLAB's "generate `.m` files, run them, collect outputs"
workflow.

## 3. Integration options (ranked safest first)

### Option A — File-based handoff (recommended first slice)

Pattern: agents generate `.m`, `.csv`, and JSON files; the user runs MATLAB
outside the app; the user drops the result file back into the workspace; an
"importer" agent ingests it.

```
agent(prompt → .m + input.csv) → artifact         (Harness Studio)
                ↓
            user runs MATLAB / Octave manually    (outside the app)
                ↓
       result.csv / result.png                    (workspace file)
                ↓
agent(reads result → report)                       (Harness Studio)
```

Pros: zero new code paths, zero security risk, works for users without
MATLAB licensed. Cons: not automated.

### Option B — Consent-gated MATLAB batch invocation

Pattern: a hook script (`.harness/hooks/run_matlab.sh` or `.ps1`) runs
`matlab -batch "run('script.m')"` after explicit consent. Reuses the
existing hook execution engine.

Requires:

1. `harness.envCheck.matlab` — a startup check that probes `matlab -batch
   "disp('ok')"` and reports availability + version.
2. Consent dialog displays the exact `.m` file and the working directory.
3. 30 s timeout already enforced.
4. stdout/stderr captured to audit log.
5. Output `.png` and `.csv` files written under `.harness/artifacts/<run>/`.

Pros: works headlessly, audited. Cons: still synchronous, no streaming.

### Option C — Octave fallback for simple scripts

Pattern: if MATLAB isn't installed but Octave is (`octave --version`), use
Octave for scripts that don't depend on toolboxes. Cheap fallback for
beginners.

### Option D — MATLAB Engine API for Python

Pattern: if Python + `matlab.engine` is installed, drive MATLAB as a library
from a Python subprocess. Allows multi-call sessions.

Pros: best for parameter sweeps. Cons: requires both Python and MATLAB
licenses; adds a Python dependency to the hook layer.

### Option E — MCP MATLAB tool (later)

If/when the MCP server (see `CLI_MCP_PLAN.md`) lands, add a `run_matlab`
tool that wraps Option B. Same consent semantics, but reachable by any
MCP-aware coding agent.

## 4. Environment checks (must run before any MATLAB execution)

```
{
  "matlab": { "found": false, "version": null, "path": null },
  "octave": { "found": false, "version": null, "path": null },
  "python_matlab_engine": { "found": false, "version": null }
}
```

Implementation: a Rust `check_matlab_environment` command that tries:

1. `matlab -batch "disp(version)"` → parse first line.
2. `octave --version` → parse semver.
3. `python -c "import matlab.engine; print(matlab.__version__)"` →
   parse last line.

Each probe must:

- Use a 5-second timeout.
- Run in the workspace working directory.
- Capture stderr without panicking.
- Cache the result for the session; expose `Refresh` in Settings.

**Never claim MATLAB works without this probe succeeding.**

## 5. File handoff format

```
.harness/matlab/
  inputs/<runId>/
    params.json            # generated by Parameter Generator agent
    input.csv              # tabular input (optional)
    script.m               # generated by Code Worker agent
  outputs/<runId>/
    result.csv             # captured by output capture agent
    figure-*.png           # plots written by saveas(gcf, ...)
    stdout.log             # captured from -batch
    stderr.log
    exit-code.txt
  artifacts/<runId>/       # mirrored into the global artifacts viewer
```

The agent prompts must instruct MATLAB to write `result.csv` and any
`figure-*.png` files into a known directory. The MATLAB hook is responsible
for setting the working directory before `run('script.m')`.

---

## 6. Safety constraints

- **Default-disabled**. Even if MATLAB is detected, `run_matlab` must be
  opt-in per workspace via Settings.
- **Explicit consent per call** — same dialog as `execute_hook`.
- **Path scoping** — the generated `.m` files must live under
  `.harness/matlab/inputs/<runId>/`. The hook refuses to run paths outside
  this tree.
- **Network policy** — the hook should optionally run MATLAB with
  `-noFigureWindows -nodesktop -nosplash` and consider a process sandbox
  later (AppContainer on Windows, sandbox-exec on macOS, bubblewrap on
  Linux).
- **License risk disclosure** — Settings must show "MATLAB requires a
  paid license; you are responsible for compliance."
- **Output redaction** — captured stdout/stderr passes through the same
  secret-masking pipeline as agent outputs.

## 7. Beginner demo project (deferred until Option B lands)

**Title:** "Antenna Array Factor Sweep"

**Inputs:** number of elements (N), spacing/λ (d), steering angle (θ₀).
**Agents:**

1. *Parameter Generator* — emits `params.json` with a grid of (N, d, θ₀).
2. *Script Author* — emits `script.m` that computes the array factor over a
   1° angle grid and writes `result.csv` + `figure.png`.
3. *MATLAB Runner* (hook) — consent-gated; runs `matlab -batch`.
4. *Result Analyzer* — reads `result.csv`, finds the main-lobe HPBW and
   sidelobe level, writes a Markdown report.
5. *Report Writer* — assembles report + embeds figure into an artifact.

Deterministic verification: for known (N, d, θ₀) the HPBW is computable
analytically; the test compares within tolerance.
